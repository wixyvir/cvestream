- **Stale devcontainer venv** (`.devcontainer/compose.devcontainer.yml`): the anonymous `/app/.venv` volume can survive a container recreate and keep the old venv after a `uv.lock` change; document `docker compose up --renew-anon-volumes` if it happens.

## Deferred from: code review of 1-4-euvd-and-kev-ingestion.md (2026-10-26)

- **A wrong-typed optional field drops the whole record** (`src/cvestream/sources/cisa_kev.py`, `src/cvestream/sources/euvd.py` payload models): optional text fields are typed `str | None`, so a non-string `knownRansomwareCampaignUse`, `shortDescription`, `description` or `product_version` fails validation and the record is skipped, losing a KEV flag or a vulnerability. Documented as deliberate in `docs/sources.md`; a catalogue where every entry fails is now a contract error. Revisit with lenient coercion (non-strings become `None`) if drift shows up.
- **A `/kev/dump` outage blocks EUVD search ingestion** (`src/cvestream/sources/euvd.py`, `EuvdAdapter.fetch`): the fetch is all-or-nothing and loads the dump first, so a dump failure also stops `/search` progress. Spec-mandated; revisit with failure isolation in story 1.6 or a separate `eu_kev` adapter.
- **Decompression amplification before the size check** (`src/cvestream/http.py`, `_read_body`): httpx decodes one network chunk at a time, so a single compressed chunk can expand far past `max_bytes` in memory before it is counted. Bounded by the chunk size; revisit if a source serves compressed bodies.

## Deferred from: code review of 1-5-correlation-state-and-publication-decisions.md (2026-10-26)

- ~~**`--debug` has no effect** (`src/cvestream/cli/main.py`): the root callback stores `CliState(debug=...)`, but nothing reads it, so an unexpected error always prints Typer's Rich traceback (exit 1). The project rule is "traceback only with `--debug`". Seen with an invalid `state.url` (fixed at the source in 1.5). Wire `pretty_exceptions_enable`/a top-level handler when the daemon arrives (1.6).~~ Resolved by story 1.6: the root app disables pretty exceptions and `main()` prints one line (exit 1), re-raising only under `--debug`.
- **SQLite deferred transactions and a second writer** (`src/cvestream/state/db.py`, `_configure_sqlite`): with `autocommit = False` the driver opens a deferred transaction; a pipeline run reads before it writes, so if another connection commits in between, SQLite refuses the write-lock upgrade at once with `SQLITE_BUSY` (the 5 s busy timeout does not cover a WAL snapshot upgrade). No second writer exists today (single daemon; `db backup` only reads). If one appears, start write transactions with `BEGIN IMMEDIATE`.
- **Advisory revisions do not merge** (`src/cvestream/pipeline/correlate.py`, `MERGE_KINDS`): advisory IDs are not merge keys, so two revisions of one advisory without a CVE or EUVD alias (CERT-FR alerte rev. 1 and rev. 2) become two vulnerabilities with the same primary ID and the same GUID. Unreachable with EUVD and CISA KEV. Review decision on wixyvir/cvestream#5 (options 1 + 3): `pipeline/run.py` now skips the colliding decision with a `publish.skipped` warning instead of aborting every run, and story 2.1 carries an acceptance criterion to make the revisions merge.

## Deferred from: code review of 1-6-feeds-served-by-the-daemon.md (2026-10-26)

- **Feeds have no item cap** (`src/cvestream/pipeline/run.py`, feed rendering in `run()`): every publication of the last 14 days is rendered, and every cycle reloads and re-normalizes the records of all of them. The story sizes a feed at a few hundred items; a broad product list (`linux`, `windows`) could reach thousands per endpoint. Consider a per-feed item cap (newest first) if feeds grow.
- **Configuration reload waits for a source fetch** (`src/cvestream/pipeline/run.py`, `cycle()`): spec-compliant (FR-23, "at the next poll cycle"), but a revoked or rotated token keeps serving until the next fetch of any source (up to 60 min + 10 % jitter), and with every source disabled the configuration never reloads. Consider a short config-revision poll that triggers a cycle when the Valkey provider arrives (story 3.1).
- **`cvestream healthcheck` always probes `127.0.0.1`** (`src/cvestream/cli/healthcheck.py`): a private listener bound to one specific non-loopback address makes the probe, and the image `HEALTHCHECK`, fail. Document it or add `--host` with the Kubernetes manifests (story 3.3).

- **A rate-limited EUVD fetch starts over** (`src/cvestream/sources/euvd.py`, `_search`): the gateway answers 403 when paged too fast, and a 403 fails the whole fetch, so every page already read is lost. The 1.5 s `page_pause` stays below the limit observed on 2026-10-31, but the limit is not documented. Option 2 of the trial comment on wixyvir/cvestream#6, not chosen for now: after at least one successful page, treat a 403 on `/search` as rate limiting, back off (30 s, then 60 s) and resume from the same page. Not every 403 (EUVD also answers 403 to malformed parameters).
